# Localization

## Supported Contract

English (`en`), Lithuanian (`lt`), and Russian (`ru`) are supported with English fallback. Semantic PHP catalogs under `lang/{locale}` are the canonical application source and are shared with Inertia; do not create a parallel client-side JSON/JavaScript catalog. Root `lang/{locale}.json` files are the narrow server-only compatibility catalog for installed Laravel packages that call `__()` with English literal or dynamic literal keys. They must remain locale- and placeholder-complete, are not shared as a second frontend store, and must not be expanded for first-party semantic copy.

`Sutelio` is a proper noun and remains exactly `Sutelio` in English, Lithuanian, and Russian. Translate complete surrounding sentences and apply locale-appropriate grammar and punctuation there; do not translate, transliterate, inflect, or concatenate the product name itself.

Locale resolution follows authenticated account preference, encrypted five-year device cookie, session, browser `Accept-Language`, then English fallback. Browser language is only the initial presentation hint: a guest without a prior explicit device/session choice receives the mandatory first-run dialog. A confirmed guest choice is stored in session and the encrypted HTTP-only cookie; login synchronizes the account preference back to the device, registration persists the selected locale, and authenticated changes update both account and device state.

The server shares the selected locale, first-run state, extensible language option catalog, owned SVG flag URLs, and bounded first-run preview copy with Inertia. `UserLanguage` also publishes the locale week-start default: English uses Sunday; Lithuanian and Russian use Monday; a subsequent explicit Sunday/Monday choice remains authoritative. Auth and authenticated shells use the same selector. The first-run dialog translates its own complete copy immediately while the user compares choices, then confirmation triggers a normal Inertia locale update so the complete application, document `lang`, formatting, persistent layout headings, Settings, and onboarding refresh together. NativePHP phone/tablet builds use this same Laravel/session/cookie boundary rather than a second native preference implementation.

On Android, NativePHP mirrors Laravel cookies between its app-private cookie store and the Chromium WebView. A data-preserving APK replacement or a SQLite-only reset intentionally retains an already confirmed language and therefore must not be described as a fresh first launch. First-run QA uses a clean disposable install; when a physical-device database must be preserved, reset only Sutelio's NativePHP/WebView cookie and guest-session state before the cold launch. Normal upgrades must never erase this state or force the dialog to reappear after an explicit choice.

The selected locale and text direction are shared to the frontend and the Inertia Blade document language. `TimeZoneRegion` owns translated group identities and the page-scoped `TimeZoneCatalog` retains every canonical PHP IANA identifier exactly once. The shared Reka combobox searches localized display text, UTC offsets, humanized city names, and original identifiers. PHP ICU supplies server display names where available; browser `Intl.DateTimeFormat` localizes the visible fallback on NativePHP builds without PHP ICU. Browser system-timezone detection is network-free progressive enhancement, never an authorization or validation boundary, and never replaces an explicit saved choice. User timezone, date format, time format, and first-day-of-week preferences drive presentation and query boundaries; canonical timestamps remain storage values.

Native email assistance uses the same semantic EN/LT/RU catalogs for remembered-history labels, device chooser guidance, selection/removal actions, and loading/cancellation/success/timeout/failure notices. No native source owns user-facing copy, and web/iOS fallback does not expose unavailable Android controls.

## Contributor Workflow

1. Add a stable semantic domain key to English.
2. Add the same nested key and placeholder set to Lithuanian and Russian.
3. Translate complete sentences; do not concatenate fragments or derive labels by title-casing stored enum values.
4. Use pluralization and named placeholders where grammar or counts vary.
5. Use shared frontend/server formatters for date, time, relative time, number, percentage, and list output.
6. Translate labels, placeholders, actions, headings, loading/empty/error/success/confirmation text, validation, notifications/email, page titles, accessibility names, and end-user API messages.
7. Reuse `ui.common.states.loading`, `opening`, `processing`, `processing_hint`, and `uploading` for the shared foreground-operation overlay. Keep each value as a complete natural sentence or phrase with key/placeholder parity across EN/LT/RU; feature components may add narrower local status copy but must not fork the global catalog.
8. Add the language to `UserLanguage`, the matching frontend union, owned flag asset, and bounded preview/name catalogs when extending supported locales.
9. Run `php artisan test --compact tests/Feature/FrontendLocalizationTest.php tests/Feature/LanguageSelectionTest.php tests/Feature/LanguageSelectionFrontendTest.php tests/Feature/GlobalOperationFeedbackTest.php` plus affected page/notification tests, then frontend type/lint/format/build and desktop/phone/tablet browser checks.

Third-party and browser failures are untrusted presentation input. Never render a package `error`, `Error.message`, DOMException text, or server-provided exception sentence directly. Branch on a stable typed error or application-owned code, map it to a semantic catalog key, and use one localized safe fallback for unknown failures. Accessible names must also be bound to the current semantic translation explicitly when a component library derives `aria-label` from DOM text, because an initially derived name may not react to a later Inertia locale change.

When an installed server package itself wraps an English literal with Laravel's `__()` helper, translate that exact package-owned key through the narrow root JSON catalogs instead of editing `vendor`. Tests must derive the active literal and dynamic-literal caller keys from the installed package source and enforce EN/LT/RU key, placeholder, and non-empty-value parity so dependency upgrades fail visibly.

Laravel validation is a server-owned presentation contract shared by Form Requests, Fortify, Inertia, and the versioned API. Every framework rule shipped by the installed Laravel version has concise corrective EN/LT/RU copy, and every first-party request field has a locale-parity human label, including wildcard collection paths. Ambiguous identifiers receive the narrowest contextual override: for example, profile and registration `name` is a person's name while the shared entity `name` remains a title. Manually constructed validation messages must translate `validation.attributes.*` before substituting `:attribute`; raw request keys and dynamic machine identifiers are never user-facing copy.

Tests verify locale key shape, non-empty values, placeholder parity, suspicious exact English copies, fallback, critical page rendering, complete Laravel authentication/password/validation messages and human attribute coverage, typed client-error mappings, localized notifications, complete timezone grouping, browser detection, and locale/timezone-aware output. Locale-neutral templates, product names, technical identifiers, and examples require a narrow documented test allowlist. A missing human-quality translation must retain key parity and use the documented fallback honestly; it must never return a raw key in a critical flow.

Notification rows and browser delivery must call the shared typed content resolver so reminder titles/bodies and safe fallbacks cannot diverge. Today/Earlier grouping uses the server-provided date key derived from the saved IANA timezone; browser-local clock/timezone guesses are not a localization boundary.

Guided onboarding uses the dedicated `lang/{locale}/onboarding.php` semantic catalog for every step, action, save/recovery state, validation summary, role-aware safety explanation, and result fact. Language selection persists through the canonical preference action and immediately renders the redirected step in the chosen locale. Result totals use locale-aware one/few/many/other keys; step titles, descriptions, and actions are complete messages rather than concatenated fragments.
